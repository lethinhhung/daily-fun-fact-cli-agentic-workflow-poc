# Daily Fun Fact CLI

The main purpose is to build the workflow from spec, generate it, then use that workflow to develop the Daily Fun Fact CLI.

This repo has two parts:

1. **Workflow CLI** — a spec-driven development tool that transforms specifications into working code through a structured pipeline. The workflow itself is built from specs first, then used to develop the target project.
2. **Daily Fun Fact CLI** — the target project built using the workflow. A CLI tool that prints a fun fact generated by an LLM.

## Tech Stack

- TypeScript
- Node.js
- Jest (testing)
- npm (package manager)

## Project Structure

```
├── specs/
│   └── core-spec.md              # Project specification
├── workflow/
│   └── specs/
│       ├── core-spec.md          # Workflow CLI specification
│       └── commands/             # Command specs (init, code, feature, debug)
├── src/                          # Generated source code (after workflow code)
├── tests/                        # Generated tests (after workflow code)
└── package.json                  # Generated config (after workflow code)
```

## Workflow

This project is developed using a spec-driven workflow CLI. The workflow reads specifications and generates working code through a structured pipeline:

```
specs/core-spec.md
       ↓ init
derived-spec/ (architecture, implementation, tests)
       ↓ code
src/ + tests/ + package.json
       ↓ feature (iterative)
specs/new-features/*.md → specs/features/*.md → derived-spec/ → src/ + tests/
       ↓ debug (iterative)
error analysis → src/ fix → tests pass
```

### Commands

| Command            | Description                                                 |
| ------------------ | ----------------------------------------------------------- |
| `workflow init`    | Bootstrap derived specs from the core spec                  |
| `workflow code`    | Generate source code, tests, and config from derived specs  |
| `workflow feature` | Add features via pipeline: new-feature → spec → code → test |
| `workflow debug`   | Analyze errors, apply fixes, and re-run tests               |

See `workflow/specs/commands/` for detailed command specifications.
